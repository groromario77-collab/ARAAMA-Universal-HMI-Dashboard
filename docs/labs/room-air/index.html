ESP32 / DHT22 / MQTT

Room air on a tablet

A thermometer gives you one number. I wanted to see what happens to both temperature and humidity after opening a window. One DHT22 and one MQTT message are enough to build both gauges and their history.

Try the same project without the board

Download sketches, simulator and both ARAAMA projects (ZIP)

What to put on the bench

An ESP32-WROOM-32 development board, USB data cable, jumper wires, Arduino IDE with the Espressif ESP32 board package, an Android 8+ device and an MQTT broker reachable from both devices on your local network.

A three-pin DHT22 module with a built-in data pull-up. Follow the labels on the module.

The supplied panel was checked in 0.1.10. For a small MQTT panel built by hand, the lighter 0.1.5 is also available. ARAAMA 0.1.10 · 110 MiB · ARAAMA 0.1.5 · 39 MiB

Wire it with the USB cable unplugged

  • 3V3 → VCC
  • GPIO18 → DATA
  • GND → GND

Sensor wiring reference

Upload the sketch and inspect the first message

RoomAir/RoomAir.ino

Extract the ZIP. Open the .ino inside its matching folder in Arduino IDE, select ESP32 Dev Module and your serial port. In Library Manager install PubSubClient and DHT sensor library (Adafruit), accepting required dependencies. Enter your Wi-Fi name and local broker address in the empty constants at the top of the sketch. Fill in passwords locally if required. The example uses MQTT on port 1883 on a trusted local network.

Upload, then open Serial Monitor at 115200 baud. Once a sensor read succeeds, one JSON message is printed every five seconds. With the network fields empty the sensor still prints locally. With the broker connected, the same message is also published here:

lab/room-air/state
{"temperature_c":21.4,"humidity_pct":51.3}

The DHT22 supplies both fields. A failed reading is skipped, so a disconnected sensor does not turn into a zero on the chart.

Try the same project without the board

The simulate.py generator stands in for the ESP32 and its sensor. Every five seconds it calculates sample readings on your computer. The values follow a smooth mathematical curve. Once you send them to a broker, ARAAMA receives ordinary MQTT messages and plots their values.

1. Preview one message

Download and extract the ZIP above, then open a terminal in the folder containing simulate.py. This step only needs Python 3. The command prints one line and exits:

python simulate.py room --count 1
lab/room-air/state {"temperature_c":22.0,"humidity_pct":49.6}

2. Send readings to the tablet over MQTT

You need a running MQTT broker reachable from both devices and the Mosquitto client on the computer. Check that mosquitto_pub --help runs in your terminal. Replace the example address 192.168.1.20 with your broker’s address:

python simulate.py room --host 192.168.1.20

Leave the terminal open. The default port is 1883. If the broker requires a password, configure publishing credentials in the local mosquitto_pub configuration file and reading credentials in ARAAMA.

3. Compare the gauge with the message

In ARAAMA, open Settings → Projects and load RoomAir/panel.json. Export any existing project first. Under Network, replace broker.example with the same broker address and select Run. Compare the number in the terminal with the gauge. After a few messages, points will appear on the chart.

4. Switch to a physical sensor

Stop the generator with Ctrl+C. Set the same broker in the sketch and start the ESP32. The topic and field names match, so the cards will start showing the physical sensor’s readings.

Build the panel in ARAAMA

RoomAir/panel.json

To reproduce the illustrated layout, open Settings → Projects, export any existing work and open the matching panel.json from the ZIP. In Network change broker.example to your broker and enter its credentials. Open Run. The two gauges and the charts share two tags. Compare the gauge with the latest MQTT message, then wait for a few updates to appear on the chart.

To build it by hand, open MQTT search while messages are arriving. Select the topic above, pick the two JSON fields below and save each binding as a tag. Set the units, add an analog gauge for each tag, enable history and reuse the same tags for the trend cards.

  • $.temperature_c → °C
  • $.humidity_pct → %
